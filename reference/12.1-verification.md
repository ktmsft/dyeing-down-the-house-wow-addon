# 12.1 — what still needs reading off the PTR

Everything in this file is a thing the addon currently **assumes**. Each one is
marked in the source too, so nothing here is the only record of it. The rule in
`Data.lua` has always been that an ID is read from the game or it doesn't ship, and
12.1 is PTR-only, so this is the list of what's outstanding rather than a pile of
quiet guesses.

Run `/dye probe` in the PTR client. It opens a window you can select and copy out of.

---

## 1. The nine item IDs — blocking

`ns.DYES` in `Data.lua` ships with `id = nil` for all nine. Counting still works
(Core matches on the exact item name and learns the ID the first time one lands in
a bag), but nothing counts a dye you've never held, and pricing can't reference one.

**How:** log in, collect the mail from Hestia Forlath in Silvermoon, then
`/dye probe items`. It walks bags, bank, Warband bank and the mail, and prints any
"… Housing Dye" it finds as a line you can paste straight into `ns.DYES`.

| Item | ID |
|---|---|
| Black Housing Dye | ? |
| Blue Housing Dye | ? |
| Brown Housing Dye | ? |
| Green Housing Dye | ? |
| Orange Housing Dye | ? |
| Purple Housing Dye | ? |
| Red Housing Dye | ? |
| White Housing Dye | ? |
| Yellow Housing Dye | ? |

Confirm the **names** at the same time. The whole name-matching fallback rests on
them being exactly `"<Color> Housing Dye"`, and Blizzard's post only spells out a
few of the nine.

## 2. How many herbs make one dye — blocking for every number on screen

`ns.HERBS_PER_DYE = 10`, because it was 10 herbs → 1 pigment → 1 dye and Blizzard
described the change as removing the middle step, not repricing it. They never
stated a ratio.

If it's wrong, every Makeable, Cost and "flowers still short" figure is wrong by the
same factor — so this is worth checking early. Stand at a Dye Station with a stack
of one herb and see what it asks for. It's a one-line fix in `Data.lua`.

---

## 3. Nine shades whose family is inferred

These carry `guess = true` in `ns.SHADES`, and the window prints "family not
confirmed" under them, so nobody is misled in the meantime. Getting one wrong
misfiles a name in a reference list — it never miscounts anything.

**The four ex-teal shades.** Blizzard said teal split between blue and green
without saying which went where. Un'Goro Green went to green on its name; the other
three to blue, because Teal Dye Pigment converts to Blue Housing Dye.

- Kul Tiran Steel → blue?
- Tidesage Teal → blue?
- Vortex Teal → blue?
- Un'Goro Green → green?

**Five of the new colors** whose name doesn't name a family. Note there is no pink
family, so both pinks have to land somewhere else.

- Klaxxi Amber → yellow?
- Aethril Pink → purple? (Aethril is a purple herb)
- Faded Mana → purple?
- Stonetalon Brick → red?
- Petal Pink → red?

`/dye probe swatches` may answer all nine at once if the swatch grid carries an item
ID per color. If it does, it's also worth re-deriving the other 68 from it rather
than trusting the old recipe-derived mapping.

The test suite asserts this count is 9. Dropping one means updating that number —
deliberately, which is the point.

## 4. The herb → color map

Carried over wholesale from the pigment each herb milled into, on the reasoning that
removing the pigment step doesn't change which herbs are which color. **Every herb
that fed teal now feeds blue**, following the pigment conversion.

Corroborating rather than proving it: Tranquility Bloom was a teal/white herb, and
one of 12.1's new blues is called Tranquility Blue.

This is the largest untested assumption in the addon by volume — 96 herbs — but also
the lowest-risk one to be wrong about in a small way, since a misfiled herb only
moves it between two color pools. Worth spot-checking a handful of ex-teal herbs at
a station (Bruiseweed, Starflower, Silkweed, Marrowroot).

---

## 5. The dye panel's frame shape — already known broken

Every path `Housing.lua` was verified against in July resolves to nil on the PTR,
which is why the "Dye Needed" box stopped appearing. The panel has visibly been
rebuilt: a swatch grid with a "Hide Unavailable" toggle, and a Cost line that now
shows a dye item icon.

`Housing.lua` now tries a *list* of candidate paths and falls back to resolving the
selected dye by shade name, so adding the real one is a single line in `PANE_PATHS`
once `/dye probe panel` reports it. What's needed:

- the pane's global path
- how the selected dye slot is reached
- where the shade's name or item ID hangs off it
- the "Cost" frame's field name, for the anchor

---

## 6. The Dye Station UI

`Crafting.lua` was deleted in this release: it decorated the Dye Crafting recipe
list and the pigment reagent picker, and Blizzard removed both ("There are no
recipes in your own crafting book to manage").

The station is a click-driven UI now, and nothing is known about its shape. Marking
the cheapest flower for a color *there* would be the natural home for what that file
used to do — `ns.GetHerbCraftVerdict` is still in Core, unused, ready for it. That's
a follow-up, not part of this release.
